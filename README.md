# 大学城美食地图

一个面向高校联盟学生的本地化美食发现网页应用。项目围绕“今天吃什么”的真实决策链路来设计：先快速筛掉不合适的店，再结合随机转盘和 AI 辅助给出可执行答案。

## 1. 项目目标

大学城周边餐饮很多，但学生常见的问题不是“没有吃的”，而是：

- 信息分散在外卖平台、社群、短视频和口口相传里
- 很难快速判断一家店是否适合当前场景
- 预算、距离、是否营业、是否适合一人食或聚餐，往往需要自己再二次判断
- 当选择困难出现时，缺少一个既能理性筛选，又能快速拍板的工具

这个项目的目标不是做一个完整的外卖平台，而是做一个更适合学生决策的“大学城美食地图”。

## 2. 产品结构

项目目前有 4 个核心页面：

### 首页 `/`

首页是整个产品的信息总入口，承担三件事：

1. 展示大学城餐饮分布和校区覆盖
2. 提供按学生场景的快速筛选能力
3. 把用户引导到“详情页”或“吃什么转盘”

首页主要模块：

- 顶部检索区
  - 支持按店名、口味、场景关键词搜索
  - 支持切换校区
  - 支持排序方式切换

- Hero 区
  - 强调产品定位：为学生解决“今天吃什么”
  - 展示当前筛选结果数量、营业中数量、平均评分等概要信息
  - 提供热搜快捷入口

- 学生筛选器
  - 品类筛选：川菜、韩餐、快餐、轻食、烧烤、食堂
  - 场景筛选：一人食、预算友好、夜宵、自习友好、宿舍聚餐、请客不掉面
  - 预算筛选：20 元以内、30 元以内、40 元以上
  - 状态筛选：只看营业中、只看收藏、只看拼单中

- 地图视图
  - 用轻量级模拟地图表达餐厅相对分布
  - 点选后右侧展示当前焦点餐厅的信息摘要
  - 不依赖第三方地图 SDK，也能完成产品表达

- 洞察模块
  - 今晚适合吃
  - 拼单热度
  - 校区覆盖

- 全量餐厅列表
  - 用统一卡片展示餐厅核心信息
  - 方便用户横向比较

### 餐厅详情页 `/restaurant/:id`

详情页承担“从看到店”的信息承接。

主要内容：

- 大图头图和基础信息
- 价格、评分、营业状态
- 签名菜、学生推荐理由
- 学生场景标签与评价标签
- 到店前先看
  - 营业时间
  - 距离和步行时间
  - 电话
  - 详细地址
- 学生好评与避雷提醒
- 同校区/同品类的相关推荐
- 快速行动按钮
  - 查看详情
  - 电话联系
  - 收藏
  - 导航跳转

### 吃什么转盘 `/lucky-draw`

这个页面同时提供两种决策方式：

- 感性决策：随机转盘
- 理性决策：AI 食力顾问

页面分成两大区域：

- 左侧 Lucky Spin
  - 轮盘按品类切分
  - 可以选择是否让 AI 候选池参与随机
  - 显示 AI Top 候选和候选池数量
  - 点击后抽中餐厅并发放优惠券

- 右侧 AI 食力顾问
  - 让用户填写决策条件
  - 根据规则对餐厅打分并排序
  - 输出一个可解释的推荐结果
  - 用户可以直接采纳 AI 推荐，也可以把 AI 结果反向喂给转盘

中奖结果弹层包含：

- 推荐餐厅大图
- 优惠券
- 倒计时
- 推荐理由
- 跳转详情或电话联系

### 我的 `/profile`

个人页目前聚焦两个用户资产：

- 我的卡券
- 我的收藏

主要逻辑：

- 展示优惠券列表和过期时间
- 展示收藏餐厅
- 根据收藏内容自动生成主题收藏夹
  - 夜宵候选
  - 自习友好
  - 宿舍聚餐

## 4. AI 辅助决策逻辑

AI 逻辑定义在：

- `src/app/lib/ai-dining-advisor.ts`

这里没有接入在线大模型，而是先用“可解释的本地评分规则”模拟 AI 决策。这样做的好处是：

- 不依赖网络
- 可控、稳定、可演示
- 逻辑透明，方便后续替换成真实 LLM

### AI 输入项

- 校区
- 场景
- 预算
- 想吃类型
- 当前心情
- 用餐方式
- 时间限制
- 是否只看营业中

### AI 打分思路

每家餐厅会基于以下维度累计得分：

- 校区是否匹配
- 场景是否匹配
- 品类是否匹配
- 预算是否合适
- 心情是否匹配该餐厅风格
- 用餐方式是否适合
- 距离是否在时间限制内
- 当前是否营业
- 评分高低
- 步行时长
- 当前拼单热度
- 正向学生反馈数量

最终输出：

- Top 1 推荐
- 若干可解释的推荐理由
- 一段摘要说明
- Top 候选池，用于转盘模式

### 为什么这样设计

这个“AI”本质上做的是把学生脑中的隐性条件显式化。用户并不一定需要一个会聊天的大模型，但一定需要一个能把“预算、时间、心情、场景”转成答案的决策器。

## 5. 收藏与本地状态

收藏逻辑定义在：

- `src/app/hooks/use-favorite-restaurants.ts`

实现方式：

- 使用 `localStorage` 持久化收藏的餐厅 ID
- 使用自定义事件同步多页面状态
- 首页、详情页、个人页共享同一套收藏状态

这样能让用户在不登录的前提下，也保留自己的宝藏店列表。

## 6. 工具函数

通用餐厅工具函数在：

- `src/app/lib/restaurant-utils.ts`

目前主要负责：

- 判断营业状态
- 提取步行分钟数
- 计算地图点位
- 生成预算标签
- 抽取校区显示名

## 7. 视觉设计思路

这个项目的视觉方向不是传统工具后台，而是“偏产品提案 + 展示型落地页”的表达方式。

主要设计原则：

- 首页强调氛围感和产品定位
- 卡片强调内容密度和可扫读性
- 转盘页强调情绪感和决策戏剧性
- 详情页强调信息的完整和可执行性
- 颜色上偏暖色食欲系，辅以深绿和米白做平衡

## 8. 技术实现

技术栈：

- React
- Vite
- React Router
- Tailwind CSS
- Motion
- Lucide React

路由配置：

- `src/app/routes.tsx`

目前已经改为 `HashRouter`，目的是兼容 GitHub Pages 静态托管，避免刷新子路由时报 404。

## 9. 部署方式

项目支持通过 GitHub Pages 自动部署。

相关文件：

- `.github/workflows/deploy-pages.yml`
- `vite.config.ts`
- `src/app/routes.tsx`

部署逻辑：

1. push 到 `main`
2. GitHub Actions 自动安装依赖并执行 `npm run build`
3. 将 `dist` 目录发布到 GitHub Pages

## 10. 本地运行

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

构建生产包：

```bash
npm run build
```

## 11. 当前项目价值

这个项目适合用于：

- 校园产品设计展示
- AI Coding 工具能力展示
- H5 产品原型落地
- 比赛答辩或课程展示

它的重点不是复杂工程能力，而是把一个贴近学生生活的真实问题，做成一个结构完整、体验连贯、逻辑清晰的网页产品。
